# Конвейер: от запроса в Вордстате до статьи на сайте

Инструкция для новой сессии. Написана после того, как этим способом за два
дня сделали 225 статей: всё, что ниже, проверено на реальных данных, а не
придумано. Цифры в скобках — реальные результаты, по ним видно, чего ждать.

## Кто что делает

Артём собирает частоты в Вордстате руками и складывает выгрузки в
`ключи/2 волна/<номер блока>/` в формате .docx. Дальше всё автоматически:
разбор → группировка → вычистка агентами → написание агентами → сборка.

## Шаг 1. Сбор в Вордстате — что важно знать

**Одно слово покрывает только свои падежи.** Это главное, что стоит помнить.
Проверено на данных: сид «сон» дал 14 183 фразы, но пересечение с сидами
«уснуть», «бессонница», «проснуться», «сонливость» оказалось **нулевым** —
все 7153 фразы из узких сидов отсутствовали в широком. Вордстат собирает по
лемме, а не по корню: «сон», «сна», «сны», «сне» придут вместе, а «уснуть» и
«бессонница» — нет.

Отсюда правило: **список сидов должен покрывать разные слова одной темы**, а
дробить внутри одного слова бессмысленно — «сон» и «сны» дадут одну и ту же
выгрузку дважды.

Для темы сна рабочий набор: `сон` · `уснуть` · `заснуть` · `проснуться` ·
`бессонница` · `сонливость` · `недосып` · `выспаться`.

**Листать до конца.** Широкий сид отдаёт вглубь до частоты 3–5 показов,
обрезки сверху нет.

**Средние сиды из двух слов дают лучший урожай.** Из 14 тысяч фраз по слову
«сон» в план не пошло почти ничего — там фильмы, матрасы, «дуб соном». Годные
темы выросли из «бессонницы», «как уснуть» и «сонливости».

**Собирать с запасом: в дело идёт примерно каждая тридцатая тема.** Из 414 тем
про сон осталось 12, из 149 про цели — тоже 12. На десяток статей нужно тем
триста сырых.

Сиды по направлениям лежат в `docs/seo/wordstat-seeds/`. Не собранные пока:
`04-dengi.md`, `05-druzhba-obschenie.md`.

## Шаг 2. Разбор .docx

```
python3 scripts/parse_wordstat_docx.py "ключи/2 волна/4" docs/seo/raw/volna-2-son.csv
```

В файлах Артёма фраза и частота слиты в одну строку («медитация517666»),
скрипт отделяет хвост цифр. Имя файла становится сидом.

## Шаг 3. Группировка в темы

```
python3 scripts/group_topics.py 300 --src=docs/seo/raw/volna-2-son.csv --csv=docs/seo/temy-son.csv
```

Первый аргумент — порог частоты. Тема определяется тремя уровнями: объект
(из сида, с нормализацией синонимов) + тип вопроса (признаки, причины, что
делать, тест) + уточнение (у женщин, на работе, в школе).

**Новые сиды надо вписать в `SEED_BLOCK` внутри скрипта**, иначе фразы
отсеются как «сид вне блоков» и на выходе будет ноль.

Порог: 300 даёт мало тем, но чистых; 100 — вдвое больше; 50 — вчетверо, но
качество падает. Для добора берите 50 и полагайтесь на редакторов.

## Шаг 4. Вычистка агентами — обязательный шаг

**Машина не отличает тему от навигационного запроса.** Проверено: попытка
ужесточить автофильтр ловила 58 дублей из 64, но заодно выбрасывала 31 годную
тему из 42. Отличить может только читающий агент.

Нарезать список по 130–180 тем на файл и запустить агентов-редакторов. В
задании обязательно перечислить, что отбраковывать:

- склейки лемматизатора («у детей без симптомов», «причина ребенок»);
- омонимы: «диссоциация» даёт школьную химию, «расстройство» — расстановку
  мебели, «депрессия» — экономику 1929 года и кардиологию (сегмент ST);
- кино, книги, песни: «Доктор Сон», «Хранители снов», дорамы, стендап
  «Переходный возраст», «расставания 1984»;
- педагогическую нормативку: ФГОС, программы воспитания, циклограммы;
- поиск услуги: «психолог Москва», «сколько стоит», «где найти»;
- диагностику и лечение — запрет ТЗ: шкалы, препараты, «как лечить»;
- клинику у детей и подростков;
- эзотерику;
- **дубли уже написанного** — это самая массовая причина отсева (около 190 тем
  из 718), агент должен сверяться по `ls docs/seo/articles/`.

Выход редактора — CSV с колонками `годна,заголовок,slug,категория,cta,частота,
ключи,причина_отказа`. Заголовок агент формулирует человеческий: вордстатовскую
формулировку в заголовок ставить нельзя.

**Ожидаемый выход: 20–25% тем.** Меньше — значит сид был широкий.

## Шаг 5. План с датами

```
python3 scripts/merge_clean_plan.py
```

Сводит части, раскладывает по 25 в день начиная со следующего свободного дня.
Отбракованное складывает отдельно с причинами.

**Перед запуском писателей ещё раз проверить остаток на дубли.** Темы приходят
из разных кластеров и выглядят по-разному: «как написать о расставании» и «как
сказать парню о расставании» — формально разные запросы, статья нужна одна. За
время работы так всплыло семь дублей уже после вычистки.

## Шаг 6. Написание агентами

По 4–5 статей на агента, **не больше трёх агентов одновременно** — на четырёх
упирались в лимит сессии. Если лимит всё же поймали: агенты обычно успевают
записать файлы до падения, проверьте `docs/seo/articles/` перед перезапуском.

В задании писателю обязательно:

1. **Роль первым абзацем, а не ссылкой на бриф.** Когда роль стоит в начале,
   голос держится по всей статье; когда она в приложенном файле — уплывает к
   третьему разделу. Формулировка: «Ты пишешь от лица Екатерины Каменской —
   практикующего психолога, выпускницы психфака МГУ, которая ведёт частную
   практику с метафорическими картами и арт-терапией. Пишешь из практики».
2. Прочитать `docs/seo/write-brief-sentyabr.md` и эталон
   `docs/seo/articles/kak-prinyat-i-polyubit-sebya.md`.
3. Точные даты `publishedAt`/`updatedAt`, `section` только для разделов.
4. **Угол против уже написанного**: назвать соседние статьи и сказать, чем
   отличаться. Без этого агент пишет пересказ.
5. Прогнать `python3 scripts/check_articles.py <слаги>` и починить замечания.
6. **Не запускать `build_blog.py`** — гонка между агентами ломает вывод.
7. Право отказаться: «если тема окажется полным дублем — не пиши, сообщи в
   отчёте». Работает: так были сняты «эмоциональные качели» и лишняя сепарация.

**Ловушки, на которых падает сборка** (перечислять в каждом задании):
эзо-фильтр ловит «предсказание», «гадание», «магия», «карма», «вселенная»,
«исполнение желаний», «карта дня», «карты подскажут» — даже в отрицании.
Отдельно: «исполнение желания» — это формулировка Фрейда, и статья про сны
на ней падает; обходится как «замаскированное желание».

## Шаг 7. Сборка, проверка, публикация

```
python3 scripts/check_articles.py --date 2026-09-20   # приёмка дня
python3 scripts/build_blog.py                          # сборка
git add -A docs/seo blog sitemap.xml index.html && git commit && git push
```

Публикация автоматическая: cron в `.github/workflows/deploy.yml` каждый день
в 09:10 МСК выкатывает статьи с наступившей датой. Темп задаётся датами, а не
настройкой.

**Ссылки вперёд роняют сборку.** Статья не может ссылаться на ту, что выйдет
позже: сборка проверяет наличие HTML. При раскладке по дням сначала выпускать
самые цитируемые статьи. Если ссылка всё же смотрит вперёд — снять разметку,
оставив текст, и вернуть позже (список вести в CSV).

**Словарные и разделы лежат в подпапках:** `/blog/slovar/<slug>.html`,
`/blog/testy/`, `/blog/sny/`. Ссылка в корень блога на такую статью роняет
деплой — так потеряли двое суток публикации и 71 статью.

## Шаг 8. После публикации

Отправить новые страницы на переобход — дневной лимит 150 адресов, квота почти
всегда простаивает:

```
node scripts/wm-recrawl.mjs   # WM_PROFILE=… WM_URLS=файл со списком
```

Аудит панелей — `.claude/skills/seo-audit/SKILL.md`, обход Вебмастера —
`scripts/wm-sections.mjs`, отчёт Google — `scripts/gsc_report.py`.

## Чего ждать по цифрам

- из 100 сырых тем после группировки останется 15–25 тем;
- из них после редакторов — 20–25% годных;
- статья пишется за 12–15 минут агентом, пятёрка — около часа;
- Яндекс начинает показывать новые статьи через 3–5 дней после переобхода;
- Google на молодом сайте почти не индексирует: 21% при 338 статьях.
